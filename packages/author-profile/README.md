# @skeleton/author-profile

작성자 프로필 — 한 사람이 여러 닉네임을 갖고 **글 · 댓글마다 골라 쓴다.** (코드 · 패키지 이름은 「프로필」, **화면에 보이는 낱말은 「닉네임」 하나**다 — 기본 문구(영어)가 `Nickname` 이고, 앱의 한국어 문구도 「프로필」을 쓰지 않는다. 계정에 붙은 이름(계정 닉네임)을 따로 두는 앱은 그것을 화면에서 숨겨 사용자에게 개념이 둘이 되지 않게 한다 — `@skeleton/auth` 의 `showDisplayName`.) 두 닉네임이 같은 사람이라는 사실은 다른 사용자에게 드러나지 않는다(같은 이름의 서로 다른 사람은 꼬리표로 구분: `이름#꼬리표`).
`createAuthorProfileApi` + TanStack Query 훅 + `AuthorPicker`(게시판 `authorPicker` 에 꽂는 선택기) + `AuthorProfileManager`(목록 · 추가 · 이름 바꾸기 · 삭제) + `createAuthorMemory`(기기 기억).
의존: `@skeleton/api-client`(`newIdempotencyKey` · `ApiRequestError`) · `@skeleton/ui`. peer: `react` `@tanstack/react-query`. **`@skeleton/board` 를 import 하지 않는다** — 둘은 서로를 모른 채 `authorPicker` 렌더 prop 한 곳에서 만난다(값은 문자열 id 하나).

## 어느 백엔드와 짝인가

백엔드 모듈 `author-profile`(+ `author-profile-jdbc`) — `account` 위에 얹힌다. HTTP 는 모듈이 연다: 기본 경로 `/api/v1/author-profiles` 가 이 패키지의 기본값(`basePath: '/author-profiles'`), `skeleton.author-profile.http.base-path` 를 바꿨다면 `createAuthorProfileApi(client, { basePath })`. 호출자는 `Authentication.name`(로그인 필요).

| 메서드 · 경로            | 이 패키지                                                                                                                                                                                              | 오류                                                                                                                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /config`            | `api.getConfig()` → `{ maxPerAccount, nameMaxLength }`                                                                                                                                                 |                                                                                                                                                                                         |
| `GET /`                  | `api.list()` → `[{ id, name, tag, createdAt }]`(내 살아 있는 프로필). **`name` · `tag` 는 `string \| null`** — 이름 없는 옛 글을 넘겨받은 첫 프로필은 `name` null, 꼬리표 방식이 꺼진 서버는`tag` null |                                                                                                                                                                                         |
| `POST /` `{ name }`      | `api.create({ name }, { idempotencyKey? })` — 201                                                                                                                                                      | 400 이름 칸(`errors[].field = "name"`, 코드는 닉네임과 같다: `Required` · `Size` · `Pattern` · `Reserved`) · 409 `AUTHOR_PROFILE.NAME_TAKEN` · 409 `LIMIT_REACHED` · 429 `RATE_LIMITED` |
| `PATCH /{id}` `{ name }` | `api.rename(id, { name })` — 200                                                                                                                                                                       | 같은 오류                                                                                                                                                                               |
| `DELETE /{id}`           | `api.remove(id)` — 204. 되돌릴 수 없고 글 · 댓글은 「삭제된 사용자」로 남는다                                                                                                                          |                                                                                                                                                                                         |
| 남의 · 없는 · 지워진 id  |                                                                                                                                                                                                        | 모두 같은 404 `AUTHOR_PROFILE.NOT_FOUND`                                                                                                                                                |

코드는 `ErrorCodes.AUTHOR_PROFILE_*`(`@skeleton/api-client`). 프로필 `id`(`prf_…`)는 게시판이 공개 작성자 id 로 쓰는 값이다 — **계정 id 가 아니다.** 이 패키지는 계정 id 를 받지도, 그리지도 않는다(기기 기억의 저장소 키 안에만 — 아래).

## 쓰는 법

```tsx
// src/author/api.ts — 앱이 한 번 만든다
export const profileApi = createAuthorProfileApi(apiClient)

// 게시판 폼에 선택기 꽂기 — board 의 authorPicker 렌더 prop 이 { value, onChange, threadAuthorId, threadLoading, invalid, disabled, onUnsettledChange, 'aria-describedby' } 를 준다
const memory = useMemo(() => createAuthorMemory(browserLocalStorage(), me.id), [me.id])
<PostEditor authorRequired={config.authorRequired}
  authorPicker={(args) => <AuthorPicker {...args} api={profileApi} boardCode={code} memory={memory}
    labels={tr.picker} onCreateProfile={profileDialog.open} createOpensDialog />} … />
<BoardComments authorPicker={…같은 함수…} … />

// 「프로필 만들기」 = 대화상자(쓰던 글 유지, 닫으면 포커스가 선택기로) — 폼 밖(페이지)에 `dialog` 를 그려 둔다
const profileDialog = useProfileDialog({ api: profileApi, title: tr.gateTitle, labels: tr.manager, alsoInvalidate: [boardKeys.all] })

// 설정 화면의 프로필 구역 — 이름 바꾸기 · 지우기는 글 쪽 이름도 바꾸므로 board 캐시를 함께 갱신
<AuthorProfileManager api={profileApi} labels={tr.manager} alsoInvalidate={[boardKeys.all]} />

// 로그아웃 때
memory.forget()
```

- `authorPicker` 는 **렌더 함수**라 안에서 훅을 쓰면 안 된다 — 위처럼 컴포넌트(`<AuthorPicker …/>`)를 돌려준다.
- 전역 오류 토스트(`QueryClient` 의 `onError`)는 `isAuthorProfileFormError(error)` 인 것을 건너뛴다 — 폼이 제자리에서 말한다(안 그러면 같은 말이 두 번 나온다).
- 첫 프로필 만들기(`onCreateProfile`)로 어디로 가는지는 앱이 정한다(설정 화면으로 이동 · 창 열기).

동작하는 모양은 `src/AuthorPicker.stories.tsx` · `src/AuthorProfileManager.stories.tsx`(가짜 서버 `src/stories/fakeAuthorProfiles.ts`).

## 선택기가 지키는 것 (실수 · 노출 방지)

- 접힌 상태는 **지금 고른 `이름#꼬리표` 하나**만 늘 보인다(제출 단추 옆, 테두리가 있는 단추 모양 + ▾). 목록은 눌러야 열린다 — 메뉴 단추 패턴(`menuitemradio` · ↑↓ Home End · Esc 는 단추로 포커스 복귀). 고르지 않았으면 「프로필 고르기」 단추.
- **처음 값**(**댓글을 받는 중(`threadLoading`)에는 확정하지 않는다** — 「쓴 적 없음」과 「아직 모름」이 다르다. 기기 기억으로 넘어가지도 않는다): ① 이 스레드에서 쓴 프로필(`threadAuthorId`, 현재 불러온 쪽 기준) → ② 이 기기가 기억하는 이 게시판의 마지막 프로필 → ③ 비어 있음(`authorRequired` 면 골라야 보낼 수 있다 — 막는 것은 board). 프로필이 하나뿐이어도 추측해서 채우지 않는다. 지운 프로필 id 는 건너뛴다.
- **스스로 채운 값의 출처**: 선택기는 값을 자동으로 채웠는지, 채웠다면 **어디서**(스레드 ① / 기기 기억 ②) 왔는지 기억한다. **기억(②)에서 온 값만** 스레드가 나중에 다른 내 프로필을 가리키면(첫 불러오기 실패 뒤 재시도 · 쪽/정렬을 넘겨 내 댓글이 있는 쪽이 보임) 스레드 값으로 다시 정한다 — 확인 없이. **스레드(①)가 정한 값은 고정**이다(쪽을 넘겨 다른 프로필의 댓글이 보여도 바뀌지 않는다). 사람이 고른 값(같은 값 다시 고르기 · 「유지」 포함)은 건드리지 않는다. 자동 값은 기기 기억에 쓰지 않는다.
- **떠 있는 질문은 미확정이다**: 한 줄 확인이 떠 있는 동안 `onUnsettledChange(true)` 로 폼에 알린다 — 폼은 제출을 막고 포커스를 확인 줄(`data-author-notice`)로 보낸다. 확인은 **다른 곳**으로 포커스가 가거나 누를 때만 버려진다(같은 폼 안, 제출 단추 포함은 아니다). 질문이 떠 있는 동안 선택기 단추의 `aria-describedby` 에 그 문장이 더해진다. **`onUnsettledChange` 를 무시하는 폼(직접 만든 폼)은 제출을 스스로 막아야 한다** — 안 그러면 확정되지 않은(질문에 답하기 전의) 프로필로 글이 나간다. 확인은 묶음(`role="group"`)이고 이름은 질문 문장, 설명은 폼이 막은 이유 문장이다.
- **표기**: 선택기 · 확인 단추 · 문장 안은 `이름#꼬리표`(간격 없음)로 같고, 관리 목록 줄(`ProfileRow`)의 이름과 꼬리표 사이에는 작은 간격(4px)이 있다 — 목록은 두 칸을 나란히 보이는 표라서 일부러 다르다.
- **긴 이름**: 접힌 단추 · 메뉴 항목 모두 **이름 부분만** 말줄임이고 `#꼬리표` 는 고정이다(전체는 글자 그대로 낭독된다 — 메뉴 항목은 `RowMenu` 의 `content`, 이름은 `aria-label`). 메뉴 폭은 내용에 맞춰 넓어지고 상한(`min(24rem, 100vw − 여백)`)이 있어 좁은 화면에서도 문서 가로 스크롤이 생기지 않는다. 확인 문장 안의 긴 이름은 줄을 바꿔 감싼다(`overflow-wrap: anywhere`).
- **게시판이 작성자를 거절하면**(`BOARD.AUTHOR_NOT_ALLOWED`) 앱의 전역 오류 처리에서 `refreshProfilesOnAuthorRefusal(queryClient, error)` 를 불러 프로필 목록을 다시 받는다(다른 탭에서 지운 프로필로 쓰려 한 경우).
- **이 스레드에서 쓴 프로필과 다른 것으로 바꿀 때만** 확인(`labels.switchNotice(스레드의 닉네임, 지금 고른 닉네임)` 한 문장 + 이름 없는 고정 글자 단추 둘 `labels.switchConfirm` 「이대로 쓰기」 · `labels.switchKeep` 「되돌리기」 — **조사(「(으)로」)에 기대지 않고** 이름은 문장 안에 따옴표로 감싼다; 단추 둘은 문장 아래에서 좁은 화면이면 줄이 바뀐다. 「되돌리기」 는 고르기 전의 닉네임으로 돌아가고, 고른 것이 없으면 「취소」). 같은 닉네임이면 묻지 않고, 확인 전까지 값은 그대로다. 확인은 값 · 이 스레드의 프로필 · 잠금이 바뀌거나 Esc · 바깥 포커스 · 바깥 누르기가 오면 닫힌다. **늘 떠 있는 경고는 없다** — 그 자체가 노출이다.
- **댓글을 받는 중**(`threadLoading`)에는 단추가 잠기고(`aria-disabled`) 고른 값이 없으면 `labels.threadLoading` 을 보인다(보이는 글자 = 낭독 이름). 이미 고른 이름은 그대로 보인다.
- **오류 연결**: 폼이 칸 오류를 보이면 그 문장의 id 가 `aria-describedby` 로 오고, 선택기 단추(프로필이 없을 때는 「프로필 만들기」 단추)에 이어진다.
- **이름 바꾸기는 한 번에 한 줄**만 열린다(오류 · 진행이 다른 줄로 새지 않는다). 저장 · 취소 뒤 포커스는 그 줄의 「이름 바꾸기」, 삭제 뒤에는 그 자리의 다음 줄(없으면 새 이름 칸). 상한 문장은 추가 칸 · 단추의 `aria-describedby`.
- 추가가 실패한 **같은 이름을 다시 보낼 때**(**네트워크 오류 — status 0 — 일 때만**)는 같은 `Idempotency-Key` — 첫 시도가 닿았어도 프로필이 둘 생기지 않는다. 서버가 답한 실패(4xx · 5xx)나 API 오류가 아닌 던짐 뒤의 다시 보내기는 새 키.
- 프로필이 하나도 없으면 「프로필 만들기」 단추(`onCreateProfile`) — 빈 메뉴를 열지 않는다.
- 사람이 고른 것만 기기에 기억한다(처음 값은 쓰지 않는다).
- **계정 id 는 DOM · aria 어디에도 없다.** 프로필 id 도 글자로 그리지 않는다(`value` 는 상태일 뿐).

## 기기 기억 `createAuthorMemory(storage, accountId)`

`localStorage` 한 겹 — `get(boardCode)` · `set(boardCode, profileId | undefined)` · `forget()`.

- 키 `skeleton.author-profile:<계정 id>:<게시판 코드>`(둘 다 URL 인코딩) — **계정 id 는 저장소 키 안에만** 있고 값은 프로필 id 하나다. 계정이 바뀌어도 서로 섞이지 않는다.
- `forget()` 은 **로그아웃 때** 부른다 — 이 모듈이 쓴 키를 모든 계정 · 모든 게시판 만큼 지운다(기기를 같이 쓰는 사람에게 남기지 않는다). 다른 저장 값은 건드리지 않는다.
- **만들 때 다른 계정의 키를 지운다** — 기기에는 현재 계정의 기억만 남는다. **전제**: 한 브라우저(저장소)에서 한 번에 한 계정만 로그인한다. **탭마다 다른 계정이 동시에 로그인할 수 있는 구성에서는 서로의 기억을 지운다**(저장소를 공유하는 탭이 번갈아 만들 때마다). `sessionStorage` 를 넘기는 구성은 탭이 닫히면 기억도 사라지지만, **로그아웃 없이 끝난 세션**(탭을 그냥 닫음)의 기억은 그 탭 세션이 끝날 때까지 남는다 — 같은 탭에 다음 사람이 로그인하면 만들 때 지워진다. 그래서 계정 id 를 아는 로그인 **뒤에** 만들고(`useMemo(() => accountId ? createAuthorMemory(…, accountId) : undefined, [accountId])`), id 를 모를 때는 만들지 않는다(그 순간의 다른 계정 기억을 지우지 않게). 같은 기기에서 계정이 바뀌어도 앞 계정의 마지막 프로필이 다음 사람에게 보이지 않는다.
- `forgetAuthorMemory(storage)` 는 같은 일을 **계정 id 없이** 한다 — 로그아웃 · 계정 바뀜 핸들러는 이전 계정 id 를 이미 잃었을 수 있다. **앱은 한 곳**(예: 인증 상태가 바뀌는 `onAccountChange` 하나)에서 `forgetAuthorMemory(browserLocalStorage())` 와 쿼리 캐시 비우기를 함께 부른다.
- 저장소 접근 예외(차단 · 가득 참)는 삼킨다 — 기억은 편의다. `browserLocalStorage()` 는 접근만으로 던지는 환경과 서버 렌더에서 `undefined`(그러면 아무것도 기억하지 않는다). 모듈을 불러올 때는 저장소를 건드리지 않는다(SSR 안전).

## 문구 · 접근성

문구는 전부 `labels` prop(`AuthorProfileLabels`, 기본 영어) — ko/en 은 앱이 공급한다. 눌리는 것은 모두 테두리 · 배경이 있는 단추다(글자만 있는 단추 없음). 선택기 단추의 낭독 이름은 `labels.triggerLabel(current)` — 보이는 글자(`이름#꼬리표`)를 포함하게 쓴다. 한 줄 확인은 `role="status"` 하나(묶음 이름으로 같은 글을 두 번 읽지 않는다), 폼 오류는 `Field` 의 `role="alert"`. 색은 의미 토큰만.
