# apps/sample — Notes (참조 제품)

"이 스켈레톤으로 이런 제품이 나온다"를 보여 주는 **작지만 실제 같은** 앱. 로그인한 사람이 **노트와 첨부 파일**을 관리한다.
새 부업 프로젝트를 시작하거나(`scripts/new-project.sh --with-sample`), 새 기능의 **정본 예시**(화면 조각 하나)로 따라 쓴다 — 에이전트도 같다(루트 `CLAUDE.md` 「새 기능의 정본 예시」).
백엔드 짝은 kotlin-skeleton 의 `apps/sample`(`/api/v1/notes` · 받은편지함 · 업로드 · 내보내기 잡). 기본 `new-project.sh` 는 이 앱을 넣지 않는다.

## 한 줄로 돌려 보기

```bash
# 백엔드 레포(kotlin-skeleton)에서 — 이 레포와 나란히 있어야 한다(기본 ../react-skeleton)
scripts/dev-sample.sh        # DB · 로컬 S3 → 백엔드 :8080 → 이 앱 :5173.  로그인: user@example.com / password(아이디 `sample-user` 로도 된다 — 백엔드 샘플은 로그인 아이디를 켜고 이메일은 쓰기 때 받는다) · 메일은 mailpit(http://localhost:8025, `docker compose --profile mail up -d`)
```

이 레포에서 프론트만: `pnpm dev:sample`(백엔드는 `API_PROXY_TARGET=http://localhost:8080`, 기본값). 브라우저 e2e: `pnpm e2e:sample` — 백엔드까지 스스로 올렸다 내린다(Docker · JDK 필요, 아래 「테스트」).

## 한 서버에 프로젝트 여럿으로 열어 보기 (개발)

백엔드 하나가 요청 **Host** 로 프로젝트를 고른다(`skeleton.projects`). 같은 앱을 주소만 달리해 두 번 띄우면 프로젝트 둘이 된다 — 앱을 복제하지 않는다. `*.localhost` 는 브라우저가 알아서 이 컴퓨터로 보내므로 hosts 파일이 필요 없다.

```bash
pnpm --filter sample dev --port 5174     # http://a.localhost:5174
pnpm --filter sample dev --port 5175     # http://b.localhost:5175
```

- 브라우저가 쓴 Host(`a.localhost:5174`)가 `/api/v1` 프록시를 거쳐 백엔드에 **그대로**(+ `X-Forwarded-Host`) 닿는다(`devProxy.ts`). 백엔드는 포트를 떼고 `a.localhost` 로 프로젝트를 고른다. 오리진이 달라 로그인 · 저장소(localStorage)도 프로젝트마다 따로다.
- `localhost:5173` · `127.0.0.1:5173` · 터널 도메인은 예전 그대로 — 프록시가 Host 를 백엔드 주소로 바꾼다. 터널 도메인(`skel.…`)을 쓰려면 `server.allowedHosts` 에 더해야 한다(Vite 가 모르는 Host 는 403).
- 포트는 마음대로(`--port`). 백엔드를 다른 포트로 띄웠다면 `API_PROXY_TARGET=http://localhost:18080`.

### 응원하기 e2e 가 백엔드에 기대하는 것

`e2e/payment.e2e.ts`(운영자 화면 시나리오는 `e2e/paymentAdmin.e2e.ts` — 같은 값을 쓰고, 운영자 경로가 닫힌 백엔드에서는 건너뛴다)는 `e2e/globalSetup.ts` 가 백엔드를 올릴 때 다음을 준다 — 백엔드(`apps/sample`)가 이것을 읽어야 한다. 응원하기(`payment-jdbc` + 샘플의 `cheer/`)가 없는 백엔드에서는 통째로 건너뛴다.

구독(2단계) 시나리오 `e2e/subscription.e2e.ts` 도 같은 가짜 토스를 쓴다 — 가짜 토스가 자동결제 경로(`POST /v1/billing/authorizations/issue` · `POST /v1/billing/{billingKey}` · `DELETE /v1/billing/{billingKey}`)와 카드 등록 창(`requestBillingAuth`)을 흉내 내고, 제어 `{billing: {mode: 'decline'\|'lose'\|'error'}}` 가 다음 빌링 승인 한 번을 정한다. 백엔드가 `SPRING_APPLICATION_JSON` 으로 받는 값: 견본 플랜 주기 `skeleton.sample.subscription.period=PT25S`, 거절된 갱신의 재시도 `skeleton.payment.subscription.renewal.retry-interval=8s`(`e2e/paymentE2eConfig.ts`). 구독이 없는 백엔드(`GET /payments/subscriptions/plans` 가 404)에서는 통째로 건너뛴다. 증거 스크린샷은 `E2E_WALKTHROUGH=1` 의 `e2e/walkthrough.subscription.shots.ts`.

## 공개 페이지와 검색 노출 (SEO)

- 모든 라우트가 `handle.seo`(`titleKey` · `descriptionKey` · `indexable`)를 가진다 — `routes.test.tsx` 가 지킨다. **랜딩 · 약관 · 방침**은 노출(canonical + OG/Twitter + 랜딩의 FAQ 구조화 데이터), **로그인 · 가입 · 메일 링크 · 계정 · 로그인 뒤 화면 · 404** 는 `noindex, nofollow` 에 canonical 없음.
- 공개 주소는 `VITE_SITE_URL`(`.env.example`) — 없으면 canonical · `og:url` · `sitemap.xml` 은 만들지 않는다(추측한 주소를 쓰지 않는다). 빌드는 `vite.config.ts` 의 `seoFiles` 로 `dist/sitemap.xml`(랜딩 · 약관 · 방침) · `dist/robots.txt`(로그인 뒤 경로 Disallow + Sitemap 줄)를 낸다.
- SPA 의 한계: 첫 HTML 이 비어 있어 JS 를 돌리지 않는 링크 미리보기 크롤러는 canonical · OG 를 못 읽는다. 그런 노출이 중요하면 같은 화면을 `apps/starter-ssr`(서버가 머리를 쓴다)로 옮긴다.

## 지키는 규칙 (ESLint · 테스트가 막는다)

- 화면은 `@skeleton/ui` 부품 + 의미 토큰만 — 날 `<button>` `<input>` `<select>` `<textarea>` `<dialog>` · 날 색 · 간격 없음. 모양 CSS 는 CSS Modules 에서 `var(--space-*)` 등으로
- 서버 상태는 TanStack Query. HTTP 는 `notes/notesApi.ts` 등 한 곳, 화면은 훅만
- 글자는 `i18n/*.ts`(한국어 · 영어, 헤더의 언어 메뉴로 바꾼다), 패키지 부품의 문구는 prop 으로 화면이 `t()` 로 골라 넘긴다 — 언어를 바꾸면 그 자리에서 다시 그린다(새로고침 없음). 선택한 언어는 `notes:ui-locale` 에 저장된다
- 새 부품이 필요하면 앱에 만들지 않고 `@skeleton/ui` 에 스토리 + `play` 와 함께 더한다(이 앱을 위해 `PageHeader` · `Badge` · `Progress` · `FilePicker` · `Stat` 를 그렇게 더했다)
