# @skeleton/video

영상 올리기 · 재생 — 파일은 **브라우저가 저장소로 직접** 올리고(조각 동시 올리기 · 실패한 조각만 다시 · 새로 고침 뒤 이어 올리기), 변환은 서버의 별도 일꾼이 하며, 이 패키지는 그 진행 상태를 보이고 결과를 튼다. 백엔드 `modules/video`(+ `video-jdbc`, 저장소는 `storage`)의 짝.
의존: `@skeleton/api-client` · `@skeleton/ui`(올리기 칸이 `FilePicker` · `Progress` · `Button` 을 쓴다) · **`hls.js` 1.7.3 고정**(재생 부품이 쓴다 — 이 패키지를 안 쓰는 앱은 받지 않는다). peer: `react` · `@tanstack/react-query`.

## 어느 백엔드와 짝인가

경로는 baseUrl `/api/v1` 기준이다(`createVideoApi(apiClient, { basePath? })`, 기본 `/videos`). 응답은 envelope(`value` / `list`)다.

| 경로                         | 뜻                                                                                                                                                                                   | 이 패키지                      |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------ |
| `POST /videos`               | `{ bytes, contentType, purpose, visibility }` → `{ id, uploadId, partSize }`. 정책 · 쿼터 · 4GB 상한을 서버가 본다                                                                   | `api.start`                    |
| `POST /videos/{id}/parts`    | `{ numbers }` → `[{ number, method, url, headers }]` 조각마다 서명된 `PUT` 주소                                                                                                      | `api.presignParts`             |
| `GET /videos/{id}/parts`     | → `[{ n, etag, bytes }]` 저장소에 이미 올라간 조각(이어 올리기). 모르는 올리기면 404                                                                                                 | `api.listParts`                |
| `POST /videos/{id}/complete` | `{ parts: [{ n, etag }] }` → 목록의 한 줄(`VideoItem`). 멱등                                                                                                                         | `api.complete`                 |
| `DELETE /videos/{id}`        | 204. 올리는 중이면 멀티파트를 중단하고 영상 폴더를 지운다                                                                                                                            | `api.remove`                   |
| `GET /videos?purpose=`       | → `VideoItem[]`(올린 순서)                                                                                                                                                           | `api.list` · `useVideos`       |
| `PUT /videos/{id}/poster`    | `{ key }`(내가 `/storage` 로 올려 완료한 이미지 키) → 204. 409 `VIDEO.POSTER_PENDING` 이면 1~2초 뒤 같은 호출 반복, 422 `VIDEO.POSTER_REJECTED` 는 거절. 화면 부품은 없다(앱이 조립) | `api.setPoster`                |
| `POST /videos/{id}/playback` | → `{ src, compat?, hls?, poster, codec, w, h, durationMs, big, expiresAt? }`. 아직 `PLAYABLE` 이 아니면 409 `VIDEO.NOT_READY`                                                        | `api.playback` · `VideoPlayer` |

`VideoItem` = `{ id, purpose, visibility, status, bytes, compat, ladder, progress, failCode, width, height, durationMs, createdAt }`.
`status` 는 `UPLOADING` → `UPLOADED` → `QUEUED` → `REMUXING` → `PLAYABLE` | `FAILED` | `DELETED`, `compat` · `ladder`(호환 단 · 사다리)는 `NONE` · `SKIPPED` · `QUEUED` · `RUNNING` · `READY` · `FAILED`, `progress` 는 일꾼이 보고한 0~100(모르면 `null`), `failCode` 는 `UNSUPPORTED_FORMAT` · `CORRUPT` · `LIMITS_EXCEEDED` · `TOO_BIG_FOR_WORKER` · `PROCESSING_FAILED` · `LEASE_EXPIRED` · `UPLOAD_ABANDONED`.
**`PLAYABLE` 은 원본 단이 올라간 순간**이다 — 호환 · 사다리 트랙이 아직이거나 실패해도 재생은 된다.

## 쓰는 법

```tsx
const videoApi = createVideoApi(apiClient) // 앱이 한 번 만든다

// 올리기 칸 — QueryClientProvider 안에서
<VideoUploadField api={videoApi} purpose="note-clip" visibility="PRIVATE" labels={koVideoUploadLabels} />

// 재생 — 재생 허가를 받아 grant 로. 비공개 영상은 토큰이 끝나면 새 허가를 받아 같은 시각에서 이어 본다
const grant = await videoApi.playback(video.id)
<VideoPlayer grant={grant} refreshGrant={() => videoApi.playback(video.id)} labels={koVideoPlayerLabels} />

// 칸 없이 직접 올리기
const done = await uploadVideo(videoApi, file, { purpose: 'note-clip', visibility: 'PRIVATE', resume: true, onProgress: (sent) => {} })
```

## 재생 순서 · 화질 칩 (`VideoPlayer`)

- 처음엔 포스터 + 재생 단추뿐이다 — **누르기 전에는 영상 파일도 hls.js 도 받지 않는다.**
- 엔진: 브라우저가 HLS 를 직접 틀면(`canPlayType`, **Safari 만 믿는다** - Chromium 계열은 안다고 답하지만 내장 재생기가 이 재생 목록을 못 틀어 `MEDIA_ERR_SRC_NOT_SUPPORTED` 로 끝난다, Chromium 153 실측) `<video src>`, 아니면 MSE 가 있을 때 **hls.js light(1.7.3, gzip 약 119KB)를 누를 때 지연 로드**, 둘 다 없으면 「이 브라우저에서는 재생할 수 없어요」(단추는 막힌다).
- 순서: **마스터(자동) → (기기가 원본 코덱을 틀면) 원본 단 → 호환 단**. 큰 원본(`big`)이고 호환 단이 있으면 호환 단이 기본이고 원본은 칩에서 고를 때만 받는다. 틀 수 있는 판이 아직 없으면 포스터 + 「영상 준비 중이에요」(단추 막힘). 한 걸음이 틀지 못하면(`error` · hls.js 치명 오류) **같은 시각에서** 다음 걸음으로, 다 실패하면 안내하고 다시 누를 수 있다.
- 화질 칩은 고를 것이 둘 이상일 때만 뜬다(`controls={false}` 면 숨는다 - 앱은 `usePlayQueue` 의 `qualityOptions` · `setQuality` 를 쓴다). 이름은 실제 높이 - `자동 (1080p)` · `1080p` · `720p`(4K 는 `2160p`), 높이를 모르면 `원본`. 바꿔도 시각을 잇는다. 큰 원본인데 호환 단이 아직 없으면 호환 항목은 「준비 중」으로 흐리게 보인다(`QualityOption.pending`).
- **비공개 토큰**: `refreshGrant` 를 주면, 재생 전에 토큰이 곧(30초 안) 끝나거나 재생 중 틀지 못했는데 `expiresAt` 이 지났으면 새 허가를 받아(한 번) **같은 걸음을 같은 시각에서** 다시 튼다.
- `controlsList="nodownload"` · 내려받기 단추 없음(저장소에 영상 한 덩어리가 없다).
- `env`(이 기기가 무엇을 트는가) · `loadHls` 는 시험 · 스토리에서 갈래를 보이려고 바꿔 끼우는 prop 이다 — 앱은 주지 않는다.

## 영상 / 노래 전환 · 잠금화면 · 전체 화면 (`VideoPlayer`)

- **입력**: `grant`(서버 재생 허가) 또는 `source`(`PlayerSource = { src, audio?, poster?, compat?, hls? }` — 서버 허가 없이 같은 출처 주소를 쿠키 인증으로 트는 앱용, 만료 · `refreshGrant` 없음). `playerSourceOf(grant)` 가 허가를 주소 묶음으로 바꾼다. 허가의 `audio`(소리 판, 준비됐을 때만)가 있어야 전환이 뜬다.
- **전환**: `audio` 가 있고 이 브라우저가 HLS 를 틀 때만 「영상 / 노래」 묶음(`@skeleton/ui` `ChoiceGroup`)이 뜬다. 같은 시각 · 같은 재생 상태(멈춰 있었으면 멈춘 채)로 잇고, 노래 모드는 `<video>` 를 떼어 영상 조각을 받지 않으며 포스터를 크게 보인다. 소리 판이 실패하면 「영상」으로 돌아가 안내 한 줄과 함께 같은 시각에서 영상 걸음 순서로 튼다. `initialMode="audio"` 로 노래부터 시작한다.
- **자동 전환** `autoAudioWhenHidden`(기본 꺼짐): 영상으로 재생 중 화면이 꺼지거나 앱을 나가면(`visibilitychange` hidden) 같은 시각의 소리 판으로 넘기고 돌아와도 노래 모드로 둔다. 아이폰 시뮬레이터 실측대로 — ① 처음 재생을 누른 손짓 안에서 `<audio>` 를 `play()` 직후 `pause()` 로 깨워 둔다(`await` 하지 않는다) ② 잠글 때 OS 가 `<video>` 를 먼저 멈추므로 「재생 중이었나」는 `paused` 가 아니라 따로 모은 사용자 의도(`createPlayIntent`, 방금 1.5초 안의 `pause` 는 OS 가 한 것으로 보되(시뮬레이터에서 OS pause 와 hidden 간격이 190~290ms 였다), 멈추기 직전 0.7초 안에 실제 입력(누르기 · 키 · 터치, 문서 전체 capture)이 있었으면 · 잠금화면 / 이어폰의 멈춤 단추면 사용자 멈춤으로 본다)로 판단한다. hls.js(비 Safari)는 깨우기 없이 전환 뒤 붙인다.
- **잠금화면(Media Session)**: `title` · 포스터 · 재생 · 일시정지 · 이동. `onPrevious`/`onNext` 중 하나라도 주면 이전/다음 단추만 등록하고 ±10초는 등록하지 않는다(아이폰 잠금화면은 seek 핸들러가 있으면 ±10초만, 없으면 이전/다음만 보인다). 없으면 ±10초.
- **전체 화면**: 데스크톱 · 안드로이드 · 아이패드는 재생기 틀(`requestFullscreen`), 아이폰은 `<video>` 의 `webkitEnterFullscreen`. 노래 모드에서는 단추가 없다.
- 단계 3(재생 대기열)이 엮는 자리: `onEnded` · `onPrevious` · `onNext` · `onModeChange` · `onPlayingChange`. 재생 부품은 한 곡만 안다.
- 폰이 자동 전환의 `<audio>` 재생을 거절하면 노래 모드에서 멈춘 채로 두고 `onPlayingChange(false)` 를 보낸다. 소리 판 주소는 허가가 갱신돼도 화면이 꺼질 때 최신 것으로 바꿔 넣는다.
- 전체 화면 단추는 이미 전체 화면이면 「나가기」(`exitFullscreen`)가 된다.
- 실기기(아이폰 홈 화면 앱 · 실제 폰)에서의 화면 끄기는 못 봤다 — 시뮬레이터 실측만 있다.

## 재생 대기열 · 작은 재생기 (`PlayQueueProvider` · `usePlayQueue` · `MiniPlayer`)

- **앱 최상단**에 `<PlayQueueProvider storageKey="my-app.queue">` 를 둔다(라우트를 옮겨도 소리가 이어진다). 안쪽 어디서든 `usePlayQueue()` 로 읽고 조작한다 - `setQueue(items, { startId, play })` · `add(item, "end" | "next")` · `remove` · `move(id, to)` · `play(id?)` · `pause` · `toggle` · `next` · `previous` · `setRepeat("off" | "one" | "all")` · `setShuffle`, 읽기는 `current` · `upcoming`(「다음 곡」) · `order` · `playing` · `mode`.
- 항목: `{ kind: "media", id, title, artist?, thumb?, source: PlayerSource } | { kind: "youtube", id, title, artist?, thumb?, videoId }`.
- **저장**: 목록 · 현재 곡 · 반복 · 셔플을 이 기기(`localStorage`, `storage` prop 으로 바꿈)의 `storageKey` 에 쓰고 새로 고침 뒤 복원한다(저절로 틀지는 않는다). 모양이 어긋난 값은 버리고 빈 대기열로 시작한다.
- **노래 모드는 `<audio>` 하나를 계속 다시 쓴다**: Provider 가 쥔 요소에 곡마다 소리 판을 새로 붙인다(hls.js 도 같은 요소). 아이폰은 손짓 없는 새 요소의 `play()` 를 막으므로 요소를 새로 만들지 않아야 화면이 꺼진 채 다음 곡으로 넘어간다. 그 요소는 첫 재생 손짓(`play()`, 또는 재생기의 재생 단추)에서 깨워 둔다.
- **`VideoPlayer` 와 잇기**: `<VideoPlayer source={...} {...usePlayQueue().playerProps} />`. 재생기는 자기 `<audio>` 를 렌더하지 않고 대기열의 요소를 빌려 쓴다 - 「노래」 전환 · 화면이 꺼질 때의 자동 전환이 그 요소로 가고(`adopt`), 재생기가 사라져도 소리가 이어지며, 영상이 끝나면 다음 곡이 소리 판이 있으면 소리로 이어진다. 잠금화면의 이전/다음은 대기열로 간다. 이때 소리 판이 틀리면 영상으로 돌아가는 대신 대기열이 다음 곡으로 넘어간다.
- **영상 / 노래 선호**: 사용자가 `VideoPlayer` 의 「영상 / 노래」 로 고른 것은 곡이 바뀌어도 대기열에 남는다(`usePlayQueue().preferred`, 앱이 처음 값을 정하려면 `setPreferred("video")` 를 앱 시작 때 한 번만 - 그 뒤에는 사용자 손짓에서만 부른다(부를 때마다 지금 재생기를 그 모드로 돌리므로, 라우트 진입마다 부르면 화면이 꺼져 소리로 넘어간 곡이 영상으로 돌아간다); 기본은 노래). 노래 선호면 소리 판이 있는 곡만 틀고 유튜브 · 소리 판 없는 영상은 건너뛴다. 영상 선호면 다음 곡도 영상으로(큰 화면이 그려져 있고 화면이 보일 때) - 화면이 꺼지면 소리 판이 있는 곡만 소리로 이어 가고 선호는 그대로다. 영상으로만 되는 곡을 직접 고르면 선호도 영상이 된다.
- **큰 화면과 소리 이어받기**: 대기열이 지금 곡을 소리로 틀고 있는데 `QueueStage` 의 `VideoPlayer` 가 그려지면 처음부터 다시 틀지 않고 소리 모드로 지금 위치에서 이어받는다(`audioHost.status()`). 영상으로 바꾸면 그 요소의 지금 시각에서 잇는다. 대기열이 소리 판 없는 영상을 영상으로 틀 차례가 오면 `autoStart` · `startSignal` 로 재생기가 저절로 틀고(한 곡 반복 · 다시 틀기 포함), 브라우저가 손짓 없는 재생을 막으면(아이폰) 재생 단추가 남고 대기열은 「틀고 있지 않음」으로 본다. 영상이 실패하면(`onFailed`) 다음 곡.
- **요소 깨우기**: 재생을 시작하는 손짓(`play` · `setQueue({ play })` · `resume` · `next` · `previous`)에서 지금 곡이 유튜브 · 소리 판 없는 영상이어도 대기열의 `<audio>` 를 첫 소리 판 주소로 `play()` 후 `pause()` 해 깨워 둔다 - 나중 소리 곡의 `play()` 가 거절되지 않게. 그래도 `play()` 가 거절되면 대기열은 `playing: false` 로 바로잡는다. 엔진은 붙은 소리 판의 곡 id 를 기억해 지워진 곡 · 다른 곡을 이어 트지 않는다.
- **영상으로 틀던 곡이 화면이 꺼질 때 소리로 넘어가려면** `<QueueStage playerProps={{ autoAudioWhenHidden: true }} />` 로 켠다(기본 꺼짐 - `VideoPlayer` 와 같다).
- 사용자가 유튜브 · 소리 판 없는 영상처럼 영상으로만 되는 곡을 **직접 고르면 선호가 영상으로 바뀌는 것은 의도**다(그 뒤 곡들도 영상으로 이어진다). 노래로 돌아가려면 소리 판이 있는 곡의 「노래」 전환(또는 `setPreferred("audio")`).
- 영상 모드의 큰 화면은 대기열의 재생 · 멈춤(작은 재생기 · 잠금화면)을 따르고(`followPlaying`), 이미 그려진 재생기는 대기열이 소리를 새로 시작하면 이어받는다(`joinSignal`). 소리 모드에서 큰 화면이 열릴 때 hls.js(크롬 · 안드로이드 · 데스크톱)도 틀던 인스턴스를 그대로 두고 이어받는다.

- 잠금화면(Media Session)은 재생기와 대기열이 번갈아 묶고, 먼저 묶은 쪽이 늦게 정리돼도 나중 쪽의 제목 · 단추를 지우지 않는다.

- **건너뛰기**: 지금 틀 수 없는 곡(위 선호 · 화면 상태에 따라 소리 판 없는 영상 · 유튜브)은 차례가 와도 건너뛰고 다음 곡으로 간다. 건너뛸 곡뿐이거나 목록 끝(반복 꺼짐)이면 멈춘다(한 바퀴를 넘어 무한히 돌지 않는다). 곡이 틀리지 못하면 묻지 않고 다음 곡, 곡 수만큼 연달아 틀리면 멈춘다. 「이전」은 3초 넘게 들었으면 처음부터.
- **`MiniPlayer`**: 화면 아래에 붙는 작은 재생기(썸네일 · 제목 · 재생/일시정지 · 다음). 비면 안 그린다. `onOpen(item)` 을 주면 정보 칸이 단추가 되어 앱이 큰 화면으로 옮긴다. 문구 `defaultPlayQueueLabels` · `koPlayQueueLabels`.
- **큰 화면 `QueueStage`**: 지금 곡이 우리 영상이면 `VideoPlayer`(대기열의 `<audio>` 를 빌린다), 유튜브면 `YoutubeStage` 를 그린다. 앱 안에 한 번 두면 그동안 「화면의 재생기가 있다」로 세어져 유튜브 · 소리 판 없는 영상이 차례에 건너뛰어지지 않는다.
- **유튜브 항목**(`kind: "youtube"`): IFrame Player API 로 **영상으로만** 튼다 - 노래 모드도 전환 단추도 없다. API 스크립트는 **유튜브 항목이 처음 그려질 때만** 불러온다(안 쓰는 앱은 받지 않는다). 노래 모드이거나 화면이 꺼진 채(`visibilityState` hidden · 큰 화면 없음) 차례가 오면 건너뛰고 다음 곡, 끝(ENDED)이면 다음 곡, 오류는 **묻지 않고 자동으로 다음 곡** - `onError` 의 어떤 코드(2 · 5 · 100 · 101 · 150 …)든, IFrame API 스크립트를 못 불렀을 때(차단 · 오프라인 · 10초 무응답)도 같다. 모든 항목이 건너뛸 대상이면 멈춘다(무한 반복 없음). 스크립트 불러오기에 실패해도 다음 유튜브 항목이 다시 시도한다.
- 유튜브 재생 · 일시정지는 `MiniPlayer` 와 맞물린다(작은 재생기에서 멈추면 영상도 멈춘다). 화면이 꺼져 iframe 이 멈추면 대기열은 「멈춤」으로 본다(자동으로 다음 곡으로 넘기지는 않는다). 아이폰은 손짓 없는 iframe 자동 재생을 막으므로 유튜브 항목 사이의 자동 이어짐은 보장하지 않는다(소리 판이 있는 곡만 화면이 꺼진 채 이어진다).

- **진행 막대 · 음량 · 전체 화면 (앱 조작줄용)** - 노래(대기열 `<audio>`) · 우리 영상 · 유튜브를 같은 API 로 다룬다.

  - `controls={false}` 로 앱 조작줄만 쓸 때는 **앱이 음량 칸도 그린다**(`canSetVolume` 이 true 일 때만). 기본 `controls`(켬)에서 영상의 자체 음량 단추를 쓰면 대기열 음량과 어긋난다.
  - 유튜브의 `controls` 는 **플레이어를 만들 때만** 읽힌다 - 곡 도중에 바꿔도 그 곡에는 적용되지 않고 다음 곡(플레이어를 새로 만들 때)부터다.
  - 한계: 아이폰은 iframe 을 감싼 틀의 전체 화면을 못 하므로 유튜브 곡은 `canFullscreen` false 다(우리 영상은 `<video>` 의 `webkitEnterFullscreen` 으로 된다).

- 한계: 큰 화면의 재생기가 대기열의 소리를 빌린 노래 모드에서는 재생기 안에 소리 조작 단추가 없다(재생 · 다음은 `MiniPlayer` 나 잠금화면). 아이폰 실기기 · 시뮬레이터에서 대기열로 곡이 넘어가는 것은 이 변경으로는 아직 못 봤다.

## 알아 둘 것

- 저장소(버킷) CORS 가 `PUT` · `GET` 을 열고 `ExposeHeaders: ETag` 여야 한다(조각 응답의 `ETag` 를 읽는다).
- 올리기 취소(칸의 「취소」)는 서버의 그 영상도 지운다. 화면을 떠나거나 새로 고침으로 멈춘 올리기는 서버에 남아(마지막 움직임 1시간 뒤 서버가 치운다) 같은 파일을 다시 고르면 이어진다.
- 올리기 오류 문구는 `VIDEO.UNSUPPORTED` · `VIDEO.TOO_LARGE` · `VIDEO.QUOTA` 코드를 알고, 그 밖은 일반 문구다.
- 스토리: `Packages/video/VideoUploadField`(가짜 서버가 단계를 한 걸음씩 보낸다) · `Packages/video/VideoPlayer`(네이티브 / hls.js 지연 로드 / 다음 걸음으로 / 칩 / 토큰 만료 / 준비 중 / 못 틂).
